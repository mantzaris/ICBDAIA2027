# AI reference annotation protocol

The user explicitly specified that no human annotators are available and that
annotations must be generated by AI. This replaces the original outline's human
annotation procedure. The source plan remains unchanged as a historical record.
The resulting annotations are **AI reference labels**, not expert labels or
independently verified acoustic ground truth. Real-data scores measure agreement
with these references; exact synthetic controls separately measure correctness.

The current templates are pending work. Empty event lists must never be treated
as negative labels until an annotator explicitly completes the scene.

## Inputs, blinding, and recording

Use `blind_scene_manifest.jsonl` for opaque IDs, WAV paths, sample rate, duration,
and audio hashes. Withhold provider filenames, vessel classes, parent IDs, split
membership, controller outputs, action histories, detector predictions, and
simulator parameters. Preserve the exact annotation prompt, model identifier and
revision, generation settings, image inputs, raw responses, validation failures,
repairs, token counts, and device/runtime measurements.

Annotate from acoustic views in a separate pass before test controller evaluation.
Give each annotator the same fixed permitted views; do not expose adaptive-system
reports. Keep separate raw files in `results/ai_annotations/internvl4b/` and `internvl8b/`; the older annotator directories contain blank templates only. Different
seeds or repeated deterministic calls to one model are not independent acoustic
experts. State whether the references and evaluated controller share a backbone,
prompt examples, perception modules, or visual preprocessing. A second AI opinion
does not by itself establish independent truth.

Use scene-local time from 0 to the supplied duration (30 s real scenes; 30–60 s real mixtures) and preserve the supplied audio SHA-256. The
evaluation exporter restores original recording coordinates using the restricted
source manifest. Full-resolution samples stay unchanged; neither display
normalization nor listening gain changes the reference signal.

## Observable morphology

Stored event types are `tone`, `chirp`, `broadband`, `transient`, and `modulation`,
corresponding to persistent lines, drifting ridges, wide events, brief events,
and periodic envelopes. Harmonic families are constituent tone/chirp events
linked by `harmonic_candidate`; unresolved overlaps remain relations or
uncertainty descriptions, not extra component targets. Keep multiple coexisting structures. Use a bounding region
for diffuse events and optional ridge points for narrowband tracks. Repeated
crops of one event retain one identity.

Each event records an ID, type, time interval, frequency interval, frequency
domain (`acoustic` or `modulation`), resolution, tolerance, and uncertainty.
Modulation events additionally require the carrier band. A 12 Hz modulation peak
is not a 12 Hz acoustic tone. A peak alone cannot establish source identity,
range, source power, shaft speed, or propeller blade count.

Allowed relations are `overlaps_time`, `overlaps_time_frequency`, `continues`,
`harmonic_candidate`, `modulation_support`, `possible_same_source`,
`contradicts`, and `unresolved_association`. Source assignment remains unknown
unless separately justified by admissible authoritative evidence. Any physical
interpretation must be a hypothesis with alternatives, not an event label.

For 16 kHz files, a full 5–8 kHz carrier leaves no transition margin and is
unavailable. Short crops must reject unsupported 4 s analysis windows. Frequency
bin spacing is recorded as resolution metadata; zero-padding does not improve
physical resolving power. Absolute acoustic SPL is not inferred from unchanged
uncalibrated digital PCM.

## Coverage, completion, and reconciliation

No AI-generated coverage assertion establishes exhaustive physical negatives.
Every final record therefore has `independently_exhaustive: false`. Empty valid
responses mean only that this checkpoint supplied no events; invalid or pending
responses are explicitly incomplete. Schema-valid JSON alone does not establish
an accurate reference. Preserve invalid responses and report syntax-only closure
repairs. Repairs never invent event values.

Keep the two raw annotation passes. Reconciliation retains agreed structure,
records disagreements, and leaves ambiguous associations unresolved. Record the
reconciliation method and model separately. Report agreement by event class,
temporal boundaries, ridge/frequency coordinates, and relations. Avoid treating
model consensus as certainty. Freeze reconciled test references and their hashes
before inspecting controller performance; test disagreements cannot be used to
tune prompts or thresholds.

Run the same annotation process on exact synthetic controls, withholding hidden
generating parameters. Measure event localization, modulation/acoustic-domain
confusion, hallucinated source claims, and response to silence and altered
evidence. These controls diagnose reference-model errors but cannot establish
real-data source correctness. Real AI-reference scores and exact-control scores
must remain separate in tables, figures, and claims.

## Qiandao short-window access audit

The 12 provider clips in `data/manifests/qiandao_short_windows.jsonl` are 3 s at
52,734 Hz and are excluded from the continuous benchmark. Their label-bearing
filenames are restricted provenance, not model inputs. Segment indices have not

Any optional analysis must use supported shorter windows and disclose the
coarser resolution. Provider target labels are not component annotations.

## Implemented calibration and frozen selection

The original four-view schema prompt failed exact-control calibration. Those raw
outputs and all subsequent two-target interface trials remain in
`results/ai_annotation_*`. The final protocol uses separate fixed LOFAR 1 s and
4 s views, two DEMON carrier views (500–2000 and 2000–5000 Hz), fixed 60 dB
maximum-relative displays, and complete fixed 1 Hz DEMON mean-PSD grids. No
selected detector peaks or controller outputs enter the prompts. Acoustic views
include two exact, separately generated training demonstrations; DEMON views
include one carrier-specific training example. Target generating truth remains
withheld. These are measurement-assisted AI references.

The pinned checkpoints are InternVL3.5 4B and 8B. Both share InternVL ancestry
and Qwen3 decoder family with each other, and Qwen3 family with the evaluated
controller; they are not independent judges. The failed Qwen2.5 3B pilot remains
archived but is excluded from the final reference process.

`configs/ai_reference_eligibility.json` preregisters a per-checkpoint/type
feasibility gate: at least three required truth events, three true positives,
precision and recall each at least 0.5, and at least 80% valid relevant view
passes on twelve declared calibration seeds. Rejected identifiable typed rows
count as false positives. Fixed 4 Hz exact-control tolerance cannot be relaxed
by model/display bin widths. Optional known envelope harmonics yield neither
TP credit nor FP/FN penalties. Modulation is unscored where simulator envelope
truth is not exhaustive. The unchanged controls have 15 tones, four chirps,
three required modulation events, two transients, and no broadband events;
therefore transient/broadband cannot qualify, and modulation requires all three.
This unequal, small-sample gate is not a reliability certificate.

Choose the qualifying checkpoint with highest calibration F1 per type, breaking
ties in favor of 4B. Store raw labels from both checkpoints. Freeze source,
configuration, input-manifest, model-revision, and demonstration identities;
then run twelve separate heldout audit controls once without retuning. Raw
labels for ineligible classes remain available but do not enter primary real
agreement metrics. If no class qualifies, primary real-reference scores are
unavailable. The final `results/ai_annotations/primary_reference.jsonl` lists
every expected scene, including missing/unavailable records, and never labels
uninspected regions as verified negative truth.

## Fixed execution mode and observed scope

Before the full final-pipeline calibration, a software-only fixture replayed the
separate training demonstration images through native serial, batch1, batch4,
and pairs of similar views. Batch1 matched native serial. Batch4 was slower on
these heterogeneous prompt lengths and changed one 8B response. Batch2 preserved
all four fixture responses exactly for both checkpoints and reduced generation
CUDA time: 4B 6.46 to 5.45 s; 8B 8.20 to 7.49 s. This small fixture does not prove
serial equivalence on unseen requests. The stronger protection is using the same
fixed batch2 execution for qualification, heldout audit, and final labels.
`configs/ai_reference_execution.json` and the raw fixture records retain the
choice and hashes. Qualification never uses the fixture's acoustic answers.

Observed acoustic scope is 0–1800 Hz at 1 s and 4 s windows. Observed modulation
scope is 0–200 Hz at a 4 s window, only for 500–2000 and 2000–5000 Hz acoustic
carriers. The reference process does not inspect the 5000–8000 Hz carrier. These
limits are exported in the freeze and each primary record; predictions outside
annotated scope must not be treated as reference negatives.
